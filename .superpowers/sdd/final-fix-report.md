# Final Review Fixes — `feat/archive-core-to-c`

## Fixes applied

### 1. Avoid `malloc(0)` followed by `memcpy(..., 0)` UB

**File:** `shirotsume_tools/archive/repipack.cpp`

- `rp_decode_header`: when `header_size == 0`, the function now sets `*header = nullptr` and `*header_len = 0` instead of calling `std::malloc(0)` / `std::memcpy(..., 0)`.
- `rp_decode_header`: `entries` allocation for `entry_count == 0` was already guarded (returns early with `*entries = nullptr`).
- `rp_encode_header`: the raw table is now allocated, zeroed, encrypted, and copied only when `table_size > 0` (i.e. `entry_count > 0`). When there are no entries the header is still emitted with a file count of 0 and no trailing table bytes.

### 2. Support `Callable[[str], bytes | None]` in `crypt.replace`

**Files:** `shirotsume_tools/archive/crypt.pyx`, `shirotsume_tools/archive/writer.py`

- `crypt.replace` now accepts either a `Mapping[str, bytes]` or a `Callable[[str], bytes | None]`.
  - Mappings behave exactly as before.
  - Callables are invoked once per entry; `None` means "copy the original body", `bytes` is encrypted and written as the new body.
  - Any other replacement type or a non-mapping/non-callable `replacements` argument raises `TypeError`.
- `writer.replace_entries` signature updated to `Mapping[str, bytes] | Callable[[str], bytes | None]`.
  - Pre-validation (`missing = set(replacements)`) is now skipped for callables because the callable itself decides which files to replace.

### 3. Make public `PackEntry` backward compatible

**File:** `shirotsume_tools/archive/__init__.py`

- `shirotsume_tools.archive.PackEntry` now imports from `.writer`, which is the dataclass with the `crypt_type` field (default `1`).
- `crypt.PackEntry` (the cdef class with only `name`/`data`) remains available as `shirotsume_tools.archive.crypt.PackEntry` for internal Cython use.
- `__all__` already listed `PackEntry`, so no further change was needed.

### Tests added/updated

**File:** `tests/test_repipack.py`

Added three tests:

1. `test_public_pack_entry_has_crypt_type` — verifies that the public `PackEntry` dataclass accepts and preserves `crypt_type`.
2. `test_replace_entries_callable` — verifies that `replace_entries` works with a callable that returns `bytes` for one file and `None` for others.
3. `test_roundtrip_header_size_zero` — verifies a zero-byte header round-trips, exercising the `malloc(0)` fix.
